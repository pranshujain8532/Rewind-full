# P6 — Build the beautiful live frontend

Prerequisite: P4/P5 APIs; basic shell already exists.

~~~text
Implement P6 as a product designer and full-stack engineer.
Read 05-FRONTEND-DESIGN.md in full, the API contracts and
COMPONENT-SOURCES.md. Preserve the accepted REWIND identity.

Build a calm, premium investigation workspace with consistent tokens,
excellent typography, clear states and purposeful motion. The hero
interaction is synchronised input provenance, intervention progress and
before/after actions. Avoid a generic marketing dashboard.

Inspect the verified 21st.dev discovery pages and choose at least two
suitable accessible components when permitted source is available.
Verify exact component URLs, licences, dependencies and source code.
Import or adapt only reviewed components, recording provenance.
Do not invent registry commands, claim unperformed imports or bypass
access restrictions. Use a permitted shadcn/original fallback if blocked.

Implement the required routes and shared components.
Prioritise Session Explorer -> Investigation -> Evidence Record ->
Regression, then connect Sentinel and Preflight as their APIs become ready.
Unavailable screens show accurate capability states.

Use REST snapshot + persisted application SSE events. Counters and
confidence intervals come from backend results. Do not animate fake
trials with timers. Reconnect and refresh must recover actual state.

Show mode, evidence status, coverage and integrity separately. Include
inconclusive/unsupported/invalid states. Graph edges describe observable
provenance; do not present ancestors as proven causes.
Render hostile input as safe text. Include accessible table alternatives.

GATE:
- full evidence journey works from real API state;
- every primary button has a real effect or a clear disabled reason;
- selected event, graph node and details stay synchronised;
- screenshots inspected at 1440x900, 1280x720 and mobile width;
- no clipping, broken layout, fatal browser errors or page overflow;
- keyboard, focus, reduced motion, contrast and empty/error states work;
- reconnect and duplicate-event tests pass;
- offline mode uses bundled fonts/assets.

Review screenshots and fix the three most visible weaknesses before
declaring completion. Record source provenance, actual screenshots,
tested behaviours and any unavailable integrations in project docs.
~~~
